# 0.2.0 release verification — 2026-10-17

Scope: integrate every outstanding branch (onboarding, preview style controls, relay recovery and independent active-view status bar), plus the pending typography, cover, export and connection-management work. Existing branch history is preserved in the integration merge. One existing CI workflow covers all checks; the duplicate workflow introduced by the older branch was consolidated into it.

## Review and fixes

- Reproduced four failures before changing the implementation: a missing explicit cover silently falling back to the first article image; account/title mutation during image uploads changing the draft target; connection deletion losing settings/credentials when persistence fails; and an 80px cover title overflowing its image.
- Fixed those failures and added regression coverage. Draft operations now capture metadata and pending preview styles before asynchronous work. Form controls are inactive while sending. Cancellation before upload prevents the next side effect.
- Connection deletion rolls back on save failure and retains secrets still shared by another connection. Closing a connection check prevents a late save. Plugin unload closes its owned modals and removes their pending work.
- Fixed accessible-name labels removed by icon replacement/list rendering, and rejected prototype names as built-in font options.
- HTML/PNG exports embed remote images; failed downloads or decode errors stop the export instead of silently omitting images. Temporary export DOM is removed on failure.
- Reviewed highlighting, theme normalization, image markers, credential handling, legacy read-only migration and dependency licenses. highlight.js 11.11.1 is a new runtime dependency for selected code-language grammars; its BSD-3-Clause license is included in the bundle and third-party notices.
- Updated compatible development dependencies resolving the npm audit findings (Obsidian SDK 1.14.4, Moment 2.31.0 and source-map-js 1.2.2). No runtime Node/Electron dependency was added. Production `obsidian` stays external.

## Automated evidence

- TypeScript, 270 Vitest tests across 12 files and production build passed.
- Runtime dependency audit passed; after the compatible development updates, full `npm audit` reported zero vulnerabilities.
- Clean installation is also checked with npm 10 to match the Node 22 CI environment. CI runs `npm ci` and `npm run check`.
- Regression fixtures are synthetic and contain no live account credentials.

## Actual desktop host

An isolated macOS Obsidian 1.13.7 profile and synthetic vault were used. The user's daily vault and WeChat clients were not operated. A dedicated local DevTools port controlled only this test Obsidian instance; the user's disabled CLI setting was unchanged.

- Fresh candidate installation and real plugin loading confirmed version 0.2.0.
- Real Markdown beside a live preview, searchable theme selection, Claude Warm and Linear Night were rendered and inspected.
- A keyboard ArrowRight changed the font size from 16 to 16.5px, retained slider focus and persisted the note-specific value; reload read the value back.
- Light/dark screenshots were inspected. At an 800px-wide two-pane window, the preview pane was 378px and the style panel was contained within the viewport. This is desktop narrow-layout coverage, not mobile-device testing.
- HTML and PNG were downloaded through the actual export action. The 1354 × 2456 PNG was opened and visually inspected, including Chinese text, lists, quotation, table, highlighted code and article ending.
- Against a controlled HTTP relay on localhost, the real modal uploaded a generated JPEG cover, created a draft, wrote its account/ID into frontmatter, reopened with “update original” selected, and updated the same ID. Requests carried `publish_now: false`.
- Installed the public 0.1.2 assets in the QA vault, saved representative legacy settings, then upgraded to 0.2.0. Connections, default account, theme, author, note styles and the SecretStorage value were retained. Disabling the candidate closed its open publishing modal.
- In the real connection modal, tested and saved a new synthetic account through the local relay. Its SecretStorage ID was valid, the secret was present in SecretStorage and absent from data.json, and the connection survived reload. This also exercised the separate Obsidian settings window.
- Successful host checks recorded no captured runtime errors. An earlier test encountered a stale modal left across reload by the old implementation; modal cleanup was repaired and the create/update flow was rerun after a cold QA-window reload.

## Official preview follow-up

The initial 6f3b427 preview identified three `obsidianmd/no-static-styles-assignment` errors: standard CSS properties had been passed to `setCssProps`, which is intended for custom properties. Color and font values now use plugin-scoped CSS variables, with the actual styling in the stylesheet. In the native host, all seven color swatches retained their expected RGB values and the selected cover font retained its computed family; no runtime errors were captured. A substantive English overview was also added to the root README alongside the full English guide. The final candidate is rescanned before release.

## Distribution and limits

Target release: [0.2.0](https://github.com/joeseesun/qiaomu-publish/releases/tag/0.2.0). Required install assets are `main.js`, `manifest.json` and `styles.css`. Official preview scan, draft-asset comparison, anonymous public download, main-branch merge and directory/client acceptance are separate release gates; see the release and PR for the final recorded status.

Not covered: actual delivery to a live WeChat account, pasting into WeChat's live editor, iOS/Android hardware, every third-party Obsidian theme, and all possible remote-image hosts. The local relay tests do not substitute for live account/API permission acceptance.
