# Local image fixes — 0.2.1, 2026-10-17

## Confirmed defects and changes

- Reference-style Markdown, raw HTML images and vault-contained file URLs rendered correctly in Obsidian but disappeared during export when metadataCache.embeds omitted them. Resolve the host-generated resource URL against vault files, lazily and once per render; ordinary cached images keep their fast path. No arbitrary filesystem access is added.
- A nested note's relative image could resolve to an outer note's same-name attachment. Accept a candidate only when its resource URL matches the image actually rendered; preserve the nested file identity through copy and upload.
- A direct upload returning `http://mmbiz.qpic.cn/...` uploaded its bytes successfully but failed before draft creation/update. Both HTTP and HTTPS URLs on this exact WeChat host now count as already uploaded; unrelated HTTP hosts remain rejected.
- Missing images no longer disappear into a successful partial draft. Keep their diagnostics, block submission before any upload, and fail copy/export with a specific repair message. Finalization also refuses unresolved local sources.
- Repeated local attachments upload once per operation; all occurrences receive the same URL. Content and cover remain separate uploads because their API roles differ. No persistent or cross-account upload cache is introduced.
- A shared image reader converts static local SVGs into genuine PNG bytes for both upload and clipboard/export. External resources, dynamic SVG content, empty images and images larger than 20 MiB fail explicitly. SVG is parsed in a detached XML document and decoded as an inert image, never inserted as active DOM.
- Clipboard copy still embeds images without account/network side effects. Its success message and README point to Send to drafts for automatic uploading; clipboard bytes alone do not prove WeChat paste compatibility.

## Open-source references

Reviewed original repositories and their licenses; implementation is original, with no copied source:

- [RanceLee233/wechat-publisher](https://github.com/RanceLee233/wechat-publisher/tree/f6b81b1827bf6fddb2e211a6e60dedb051c41974), MIT: resource identity, per-operation upload reuse and strict upload completion. Avoided basename-only fallback and global identity maps.
- [jackice/obsidian-wechat-public](https://github.com/jackice/obsidian-wechat-public/tree/ebc58c32d739ea79a586104d8c8c6452f315e2a4), 0BSD: separate upload failures and image normalization. Failures are propagated here instead of leaving partial success.
- [ai-chen2050/obsidian-wechat-public-platform](https://github.com/ai-chen2050/obsidian-wechat-public-platform/tree/6036e42db4f50f5515ef62bb9e5858b0741ce02d), MIT: binary multipart transfer. Existing browser-compatible binary upload remains in use; no Node/Buffer runtime dependency was added.

## Verification

- Before implementation, the new source/transport regression tests reproduced nine failures. The final suite has 292 passing tests in 14 files, with type checking, production build and runtime dependency audit passing.
- Installed the candidate into the existing isolated QA vault, upgrading public 0.2.0 to 0.2.1. Its `data.json` was byte-identical across reload. Obsidian auto-updated this isolated profile from 1.13.7 to 1.14.4; results below are from native 1.14.4.
- Fifteen native render fixtures cover wikilinks with sizes, inline/angle/dot/root paths, Chinese spaces, reference syntax, raw HTML, nested notes, file URLs, SVG, WebP, duplicates and missing files. The same-name case now identifies both copies as the nested note's red image, instead of the outer blue file.
- The installed Copy action produced decodable images in seven representative cases, including two nested images and a real 200×200 PNG converted from SVG. Clipboard writes were captured locally for verification; the user's system clipboard was not overwritten.
- Direct transport exercised native image decoding, compression and multipart bytes, with only official HTTP responses controlled. HTTP upload responses now permit both create and same-ID update. A 4,129,956-byte PNG became an 880,729-byte JPEG; empty/21 MiB inputs and upstream error 45001 produced no draft call.
- Actual qmblog relay source at `7956d0e8` served loopback HTTP; only its official WeChat upstream was replaced with controlled responses. After supplying its ImageMagick dependency (7.1.2-33), PNG/JPEG/WebP/SVG, duplicate, nested, file URL and large-image uploads succeeded and draft contents were read back. Missing-file failure remained blocking. This corrects the earlier local test-environment ENOENT gap; it does not establish a production relay defect.
- The installed publish modal created drafts for seven representative fixtures, wrote their IDs to frontmatter, then reopened and updated the original ID. Upload logs confirm one content upload for a repeated local file and two image occurrences in the article. The missing-file modal disables Send; Copy performs zero clipboard writes and shows the missing filename.

## Scope and release gates

This patch starts from published main, leaving the unrelated browser-platform development branch intact. Version target is 0.2.1. Required assets remain main.js, manifest.json and styles.css; plugin/command/secret IDs are unchanged.

Official preview, CI, draft-asset install, anonymous public asset checks, main merge, formal directory review and client installation are recorded in the release/PR after this candidate is frozen. Passing source tests is not a claim that those later stages are complete.

Not covered: live WeChat credentials/API permissions, pasting into a live WeChat editor, iOS/Android hardware. No WeChat client or embedded WeChat page was automated. The local synthetic upstream is explicitly distinct from a real-account delivery test.
